# Languages — ar / fr / en, from the backend

## How it works
1. Backend is the source of truth: table `translations` (locale, key, value, unique locale+key), seeded by `TranslationSeeder` (58 keys × 3 locales = 174 rows).
2. API (public, no auth needed):
   - `GET /api/languages` → [{code, name, direction}] for ar (rtl), fr, en.
   - `GET /api/translations?locale=ar` → {locale, direction, translations: {key: value}}.
   - Unknown locale → 422.
3. Mobile: `LanguageContext` (default locale `ar`) fetches `/api/translations?locale=...` on every locale change and merges it over the local fallback dictionaries in `src/i18n/dictionaries.ts` (identical to the seeder). If the API is offline, the app still works in the chosen language from the fallback. Settings and Start screens show the switcher (العربية / Français / English) and the source (backend vs fallback).
4. Admin: edit any string in Filament → Translations (locale filter, key search) — no app release needed, the mobile app picks it up on next locale load.

## Adding a string
1. Add the key to `TranslationSeeder` (ar/fr/en) and to `src/i18n/dictionaries.ts`.
2. Use `const { t } = useLanguage(); t("your_key")` in the screen.
3. Run `php artisan db:seed --class=TranslationSeeder` (or full seed) and `npm test`.

## Adding a language
Add it to `App\Support\Languages::AVAILABLE`, the seeder (all keys), `SUPPORTED_LOCALES` in dictionaries, and the Filament locale select. Arabic is RTL in the API (`direction: rtl`); layout mirroring via I18nManager is intentionally not forced here (it requires an app restart) — text is fully Arabic.
